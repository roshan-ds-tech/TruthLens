## Project overview

The frontend is React 19 with Vite. Home handles signup/login; authenticated screens cover Dashboard, Cases,
New case, Analysis run, Case workspace, Image evidence, Audio evidence, Report, Evidence Library, Validation,
and Settings. Navigation and the current case/evidence/job are React state rather than durable URLs.

FastAPI exposes `/api`. SQLModel/SQLite stores users, hashed sessions, cases, evidence, findings, reviews,
settings, jobs, reports, and an append-only hash-chained custody log. Hosted mode filters cases by owner.
Ingest checks file signatures, computes SHA-256, preserves read-only originals, extracts metadata, and derives
video audio tracks. A single background worker runs deterministic analyzers, then calibration, correlation,
fusion, and persistence. Model inference is local/offline on the server.

Image checks include metadata, ELA, noise, JPEG ghosts, and copy-move. Video checks include frames,
duplicates, optical flow, face-region measurements, and frame forensics. Audio checks include noise changes,
bandwidth, prosody, and Whisper transcripts. Captions are checked against metadata and transcripts.
WeasyPrint produces PDF reports; JSON exports retain structured findings, provenance, and review state.

## Issues for Claude Code

### 1. High priority: reviewer note drafts carry across cases

**Reproduce:** In C-0003, add a note to F-VID-001. Open C-0004 and open Add note on its different F-VID-001.
The textarea contains C-0003's note about an inserted duplicate at frame 110, although C-0004's finding concerns
a road-video flow event. The carried note was **not saved** into C-0004.

**Cause:** `src/screens/CaseWorkspace.jsx:183–185` keys local drafts and note state by finding ID;
its case-change effect at line 213 clears selection/view/time but not draft/note state. Finding IDs intentionally
repeat across cases. Key by case + finding/database ID, and reset local review state on case change.

Evidence: [screenshot](../data/visual-qa-20261119/18-cross-case-note-draft.jpg).

### 2. High priority: text-file-only upload cannot start analysis

**Reproduce:** Create a case and upload `text_upload.txt` without pasting a caption. The request succeeds and
C-0008 contains E-01 of kind `text`; the form shows zero uploads and disables Start analysis.

**Cause:** `src/screens/NewCase.jsx:107` excludes text from the `evidence` array used for both rendering and
Start analysis enablement. Render uploaded text evidence and use all accepted evidence for enablement.

Evidence: C-0008, browser output `startEnabled: false`, and [screenshot](../data/visual-qa-20261119/26-text-only-disabled.jpg).

### 3. High priority: saved drafts do not reopen

**Reproduce:** Save the boundary draft C-0007, reload, then click that draft in Cases. The New case screen is
blank and says “not saved yet”; title, description, media and saved caption are not restored. The server still
retains all five evidence records, so this is a UI restoration failure rather than deletion.

**Cause:** `src/App.jsx:214` renders `<NewCase ...>` without passing `caseId={nav.caseId}`, even though NewCase's
resume effect requires that prop. After that is fixed, also restore existing text/caption state: the current resume
effect only restores title, description and non-text files.

Evidence: [blank form after opening saved draft](../data/visual-qa-20261119/28-restored-draft-missing-caption.jpg).

### 4. Hosted privacy wording contradicts the deployment

Home shows a Hosted banner but also “Runs on your device” and “Nothing is uploaded.” These are false for a
visitor using the Vercel site: evidence is sent to the Mac backend through the tunnel. The signup dialog also
calls the account local. Analysis and some report/library labels likewise say “on this device.”

Update mode-dependent copy throughout, starting with `src/screens/Home.jsx:20` and `:94`.
Settings briefly displays local-mode privacy defaults while its hosted settings request is loading.

Evidence: [hosted Home screen](../data/visual-qa-20261119/29-hosted-privacy-copy.jpg).

### 5. Visible global search is nonfunctional

Typing `nonexistent-qa-search-value` leaves all three then-current cases visible. `src/App.jsx:177–178` renders
an uncontrolled input and a shortcut badge without a query/filter or keyboard handler. This limitation is already
mentioned in repository documentation, but remains a visible unfinished feature.

### 6. Report preview pagination differs from the PDF

C-0003 preview says page 1/2 and page 2/2, while the downloaded PDF contains six A4 pages.
`src/screens/ReportPreview.jsx:109` and `:159` hardcode the page counts. The browser preview also compresses
content differently from the PDF. Render the PDF itself for a faithful print preview, or clearly distinguish the
summary preview from exported pagination.

Evidence: [browser preview](../data/visual-qa-20261119/12-report-preview.jpg),
[PDF contact sheet](../data/visual-qa-20261119/pdf-contact-sheet.png),
[downloaded PDF](../data/visual-qa-20261119/C-0003-report.pdf).

### 7. Corrupt-file error exposes a server filesystem path

Uploading `corrupt.jpg` returns a decoder exception containing `/var/folders/.../tmp....jpg` to the browser.
`backend/app/ingest/service.py:89` forwards the decoder exception. Keep full detail in server logs and return
a concise user-facing unreadable-file message.

### 8. Dashboard “Evidence analyzed” includes unanalysed drafts

At the end the tile says **28**, but only **22** evidence records belong to completed analyses; six are in the
boundary/text-only drafts. Rename it Evidence uploaded/stored or calculate the actual analysed count.

### 9. Review-before-report marketing copy does not match behavior

Dashboard says “Nothing goes into a report until a reviewer has seen it,” but export succeeded with 13 of 15
findings still pending. The report correctly labels their status. Either revise the promise to describe draft
reports with pending findings or enforce a separate finalization step.

## Detector limitations observed

- The known pasted-region JPEG received No indicators found even though weak JPEG-ghost findings were recorded.
  This is a concrete false-negative example for anyone treating the displayed verdict as an authenticity decision.
- Source JPEGs downloaded unchanged from Samplelib already contain GIMP metadata. Their Inconclusive verdicts
  cannot be counted as false positives against certified camera-original ground truth.
- Compression/bandwidth restrictions in an ordinary source video/audio can produce indicators; they do not prove
  malicious editing. The road sample illustrates why the alternative explanations matter.
- Synthetic non-speech can produce repetitive ASR hallucinations with high confidence. The logs and read-only
  evidence records show 112 repeated tokens for 8-second synthetic audio and 261 tokens for 6-second band-limited
  audio at mean confidences around 0.94/0.96. The human recording was substantially more useful, though its first
  sentence was segmented/transcribed as “canoes lid” rather than “canoe slid.” These are observations, not an ASR benchmark.
- The independently edited speech boundary was localized near 11.6 s rather than the exact known 12.0 s cut.
- No human-face flicker/deepfake or lip-sync ground-truth benchmark was completed: the tested clips reported no
  usable detected face sequence. Fully AI-generated untouched images, cloned voices, GPS/place/number conflict
  accuracy, load testing, and a full browser/device matrix remain unvalidated.
